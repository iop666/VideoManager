# VideoManager — 本地视频管理与元数据整理工具

VideoManager 是一款**本地优先**的视频管理与元数据整理软件：**Windows 端**负责扫描你硬盘上的视频、建立索引、整理元数据（分类/标签/作者/评分/备注/收藏）、生成封面与关键帧，并提供批量重命名、格式转换、统计报表与局域网服务；**Android 端**通过局域网连接 Windows 端浏览视频库。**所有视频文件与数据都保存在你自己的电脑上**，不依赖任何云服务。

> 本项目 README 的重点放在讲清一个核心问题：**「元数据」和「本地视频文件」到底是什么关系**。理解了这一章，其它功能都是顺理成章的。

---

## 🧭 一、两个世界：视频文件 vs 元数据

VideoManager 里有两层完全不同的东西，请先分清：

| | **本地视频文件** | **元数据** |
|---|---|---|
| 是什么 | 你磁盘上真实的 `.mp4 / .mkv / .avi ...` 文件 | 数据库里关于每个视频的**描述信息** |
| 谁拥有 | 你（用资源管理器就能看到、管理） | VideoManager 的本地数据库 |
| 存放位置 | 你选的任意文件夹 | 软件目录下的数据库与图片目录 |
| 会不会被程序搬动 | **永远不会** | —— |
| 丢失后会怎样 | 元数据记录仍保留（见下文「文件删除后」） | 记录丢失不会伤及文件 |

**VideoManager 从不复制、移动或删除你的视频文件**（只有你主动点「删除记录与本地文件」或执行批量重命名、格式转换时除外）。你随时可以用资源管理器随意整理文件，改完回到软件里重新扫描即可——这正是它和其它"把视频收进自己库里的播放器"最不一样的地方。

### 一条记录 = 一个视频身份

扫描/导入时，程序为每个视频文件流式计算 **SHA-256**（按内容算的唯一指纹），一条元数据记录就这样和一个视频"绑定"：

```
你的硬盘（文件本体，由你管理）
   └─ D:\视频\某合集\EP01.mp4 ──┐
                               ├── 内容指纹 SHA-256 ──► 数据库里的一条记录：
   └─ 移到别处/改名后仍同指纹 ──┘                        ├ 标题 / 文件名 / 历史文件名
                                                       ├ 时长·分辨率·帧率·编码·格式·大小
                                                       ├ 分类 / 标签 / 作者 / 评分 / 备注 / 收藏
                                                       ├ 封面图片（<sha256>.jpg）
                                                       ├ 关键帧截图（按秒抽帧，右击视频可看）
                                                       └ 添加时间 / 最后修改 / 播放次数
```

- 记录里的 `file_path` 只是**「当时扫到它时的位置」**，不是锁定的归属。
- 判断"是不是同一个视频"永远看 **SHA-256 内容指纹**，而不是看路径或文件名：同一内容的文件无论叫什么、放在哪个盘，在库里都只对应**一条**记录（自带重复检测）。

## 🔗 二、元数据与本地文件的生命周期

这是最需要理解的部分。下面的流程描述的就是软件的日常行为，你可以在「导入页」和「视频库 / 元数据页」直接观察到。

### 1. 首次导入：文件 → 记录

在导入页添加一个文件夹（可递归）并扫描，程序对每个视频文件依次做：

1. 按扩展名过滤出视频文件；
2. 用 ffprobe 读取媒体信息（时长/分辨率/编码/格式等）；
3. 流式计算 SHA-256 指纹；
4. 截取一帧生成封面（`<sha256>.jpg`）；
5. 在数据库插入一条记录，标题默认取文件名。

### 2. 再次扫描：增量处理，只有这五种可能

```
文件夹里出现 / 变化的文件
    │
    ├─ 文件没变（大小 + 修改时间一致）──────────► 跳过（增量扫描，大文件夹也很快）
    ├─ 同位置文件内容变了 ────────────────────► 刷新媒体信息，保留你改过的标题
    ├─ 库里已有同指纹记录（在别的路径/缺失/占位）─► 位置迁移：把记录"认领"到当前文件，元数据原样保留
    ├─ 全新文件 ─────────────────────────────► 建新记录 + 封面
    └─ 库里记录着、但本次磁盘上找不到的文件 ─────► 标记为缺失（记录不删，见下）
```

### 3. 文件被移动 / 改名了？重扫一次就回来

文件在软件外被移动或改名后，旧路径会失效，但**指纹还在**。此时：

- 到导入页**重新扫描该文件夹**（文件仍在原文件夹内），或扫描文件现在所在的文件夹；
- 程序按 SHA-256 找到原来的记录 → **位置迁移**，`file_path` 更新为新位置，记录回到「本地就绪」；
- 你给它设置的标题、分类、标签、评分等**全部原样保留**；
- 新文件名会被追加进**历史文件名**（只读展示），以后可追溯"这个视频曾经叫什么"。

> 只有一种情况标题会跟随新文件名：你从没手动改过标题（标题一直是旧文件的默认名）时，迁移后自动换成新文件名作为默认标题。

### 4. 文件被删除了？记录留着，标为「缺失」

删除文件、或把它移出所有已导入的文件夹后再扫描，该记录会被标记为 **missing（缺失）**：

- 元数据、封面、关键帧、播放统计**全部保留**——你可以继续管理、编辑它；
- 详情/编辑页的「本地位置」显示为 **无本地文件**；
- 默认视图（见「显示范围」）会把它藏起来，切换到「全部」或「隐藏本地」就能看到并管理。

**程序绝不会因为文件不见了就悄悄删掉你的元数据**——几千条整理好的分类标签，不会因为一次误删文件就付诸东流。

### 5. 换电脑 / 恢复备份后：重新「认领」本地文件

从备份恢复（见下节）后，库里的记录**没有路径**（备份本来就不存路径），此时它们以 **`restored://` 占位**形式存在：元数据、封面、关键帧都在，能正常浏览、编辑，只是没有指向本地文件。

要把元数据重新绑回真实文件，只需三步：

1. 确认视频文件在磁盘上（无论放在哪个文件夹）；
2. 在**导入页扫描该文件夹**（就是扫描新文件夹的普通操作）；
3. 程序按 SHA-256 逐条匹配占位记录 → 自动迁移为真实路径，并补齐该文件夹内缺失的关键帧。

这就是"备份恢复后重新扫描一遍，原来整理的元数据全回来了"的完整逻辑。

### 6. 两个防误伤的细节

- **标题保护**：重扫时如果标题是你手动改过的，绝不覆盖；只有默认标题（=文件名）才会跟随文件变化。
- **指纹先于入库**：新文件先算完 SHA-256 再写入，避免把重复文件重复入库；扫描失败的文件会跳过并在结果里报"失败"。

## 📁 三、数据都存在哪里

| 内容 | 位置 | 说明 |
|---|---|---|
| 视频文件本体 | **你指定的任意文件夹** | 程序只读，永不搬动 |
| 数据库 `videomanager.db` | 软件目录 `data/` 下 | 全部元数据（WAL 模式） |
| 封面缩略图 | `data/thumbnails/`，文件名即 `<sha256>.jpg` | 可随时删除，重扫自动重建 |
| 关键帧截图 | `data/keyframe/` | 可删除，在导入页重扫文件夹后自动补齐 |
| 备份压缩包 | 你在设置里指定的备份目录 | 见下节 |

> 打包版默认把数据放在**软件所在目录的 `data/` 子目录**（绿色版解压即用、安装版紧挨着 exe）。若安装到 Program Files 等不可写目录，会自动回退到系统用户数据目录。绿色版整包拷贝即可连同数据一起迁移。

## 💾 四、备份与恢复

「设置 → 备份与恢复」：

- **立即备份**：把全部视频元数据打包成一个 ZIP（文件名带时间到秒，自动保留最近 30 份）；
- **自动备份**：开启后，每次保存元数据都会自动执行一次备份；
- **恢复备份**：打开安全恢复向导（见下）。

### 安全恢复向导：可预览、可配置、可回滚

恢复不再是一次"清空重来"的冒险操作，而是分四步的受控流程：

1. **校验与差异分析（只读）**：选择备份文件后先校验完整性（zip 可解压、data.json 合法、每条记录 SHA-256 为 64 位十六进制、备份内重复自动去重），再与本地库按 SHA-256 逐条比对，生成差异报告：**备份独有 / 本地独有 / 冲突（同指纹但元数据不一致）/ 完全一致**，以及备份内重复、无效条目、缺封面等提示，均可在界面查看明细。
2. **选择恢复模式**：
   - **仅补缺（最安全）**：只新增本地缺失的备份条目，已有记录一概不动；
   - **本地优先合并**：冲突时保留本地元数据，只新增备份独有的条目；
   - **备份优先合并**：冲突时以备份内容覆盖本地，只新增备份独有的条目；
   - **完全恢复（清空重建）**：清空当前全部记录后按备份整体重建。
   - 除完全恢复外，**本地独有记录默认保留**，程序不会因恢复而丢弃你的整理成果。
3. **执行前自动快照**：任何破坏性操作前，自动把数据库完整副本存到软件目录 `data/restore-snapshots/`（保留最近 10 份）。恢复对数据库的全部改动在**单个事务**内完成——中途失败会整体回滚，不会留下半成品；封面/关键帧属可重建文件，个别写入失败仅警告。
4. **可回滚 + 全程留痕**：恢复完成后可一键回滚到恢复前快照；每次恢复/回滚的时间、模式、差异摘要、逐条变更明细都会记入「恢复记录」，可在设置页随时查看。

### 备份 ZIP 里有什么（以及没有什么）

```
videomanager-backup-20260905-123456.zip
├── data.json          # 全部元数据：标题/指纹/媒体信息/分类标签作者(含颜色)/评分/备注/收藏/历史文件名/关键帧记录…
├── images/            # 每部视频的封面 <sha256>.jpg
└── keyframe/          # 关键帧截图
```

- ✅ 包含：指纹、标题、媒体信息、分类/标签/作者及颜色、评分、备注、收藏、历史文件名、封面、关键帧、播放统计、时间信息。
- ❌ **不包含视频文件本身**（所以备份很小、很快）；
- ❌ 不包含文件的绝对路径——**备份因此可以在任意电脑、任意目录结构上恢复**，这正是「恢复后重新扫描认领」能成立的前提。

### 恢复后记录如何重新认领本地文件

无论哪种模式，备份数据本身不含路径，恢复出的记录（以及完全恢复重建的全部记录）以 `restored://` 占位形式存在。回到本文 **第二章第 5 节**：在导入页扫描视频所在的文件夹，程序按 SHA-256 把占位记录自动迁移为真实路径，并补齐关键帧——整理的元数据就全部回来了。

### 引用计数与物理删除分离

删除记录或恢复完成时，程序不会立即删除封面/关键帧图片文件，而是以 SHA-256 引用计数为准执行**垃圾回收**：只清理库中已无任何记录引用的孤儿封面（`thumbnails/<sha256>.jpg`）与关键帧（`keyframe/Keyframe_<sha256>_NN.jpg`）。**你磁盘上的视频文件永远不会被自动删除**——即使清理全部记录也只影响程序生成的图片。

## 🎚 五、显示范围：谁在列表里，取决于"文件在不在"

视频库与元数据页的范围切换，本质是**按本地文件存在性过滤记录**：

| 范围 | 含义 | 底层逻辑 |
|---|---|---|
| **仅显示本地** | 只看当前磁盘上真实存在的文件 | 排除缺失 + 排除 `restored://` 占位 |
| **全部** | 所有记录，含缺失与备份占位 | 不做存在性过滤 |
| **仅收藏** | 只看收藏过的记录 | 叠加收藏标记 |
| **隐藏本地** | 只看当前没有本地文件的记录（缺失 + 占位） | 反向过滤 |

> 占位与缺失记录仍有封面、关键帧和全部元数据，可正常编辑，只是「本地位置」显示为无本地文件。

## ✨ 六、功能特性

### Windows 端

- **视频导入与增量索引**：递归扫描文件夹、自动过滤视频扩展名、ffprobe 提取媒体信息、SHA-256 唯一身份与重复检测；未变更文件秒级跳过，删除文件自动标记缺失。
- **元数据管理**：分类（支持树形、自定义颜色）、标签、作者、评分、备注、收藏；元数据页支持编辑、按名称/数量排序的候选下拉与「仅本地/全部」等范围切换。
- **关键帧概览**：扫描/导入时按时长自动抽帧（≥300 秒 12 张 / ≥180 秒 9 张 / ≥60 秒 6 张 / ≥1 秒 3 张），统一压缩为 960px JPEG；在视频库与元数据页**右键视频**打开关键帧抽屉（顶部显示时长/帧率/总帧数），点小图放大。
- **封面显示**：视频库封面支持「横屏比例」（16:9 黑底居中）与「正常比例」即时切换。
- **元数据批量操作**：元数据页**长按封面（0.55 秒）**或点工具栏「多选」进入批量选择（单击/右键切换，选择集跨分页保留），可批量收藏/取消收藏、设置分类/作者、追加标签、修改备注，以及删除记录（仅移除记录或连同本地文件，缺失/占位记录自动降级）；封面与关键帧等生成文件由引用计数 GC 清理，绝不会误删未选中的视频。
- **批量重命名**：查找替换/正则/前缀/后缀/大小写规则引擎 + 批量改扩展名，实时预览、冲突检测、一键撤销。
- **格式转换**：FFmpeg 集成，单个/多个文件或整个文件夹导入，三档画质（CRF 高/中/低）等比缩放，转换队列实时进度。
- **任务控制**：任务页对每条任务提供 暂停/继续/取消/重试/删除——扫描运行中可暂停（当前文件完成后生效）与取消；转换运行中可取消（自动清理半成品输出）；失败/已取消的任务可读原参数一键重试；「清空记录」只清理历史，不影响进行中与排队任务。
- **统计报表**：总数/总时长/总大小，分类/标签/作者分布可点击跳转筛选。
- **播放集成**：调用 PotPlayer 播放，自动检测或手动配置播放器路径。
- **局域网服务**：内置 HTTP 服务（Bearer Token + 6 位配对码），为 Android 端提供列表/详情/缩略图/同步 API；**默认关闭**，开关状态自动记忆。
- **主题系统**：跟随系统/明亮/深色 + 11 种中国色配色；分页（2–525/页）与网格/列表视图自定义。
- **数据备份与恢复**：一键 ZIP 备份元数据 + 封面 + 关键帧，支持自动备份；恢复为安全向导：完整性校验 + 差异预览 + 四种合并模式 + 自动快照可回滚 + 全程操作日志（详见上文）。

### Android 端

- 局域网连接 Windows 端，浏览视频库（网格/列表）、搜索、按分类/标签/作者/方向筛选、排序。
- 同步 Windows 端元数据（含离线缓存），断网后可浏览最近同步的数据。
- 本地与网络缩略图展示、视频详情查看；跟随系统/明亮/深色主题与 Windows 端配色一致。

| 端 | 框架 | 数据库 | 说明 |

## 📁 目录结构

```
VideoManager/
├── desktop/            # Windows 端 (Electron + Vue3 + TS)
│   └── src/
│       ├── main/       # 主进程：窗口、SQLite、IPC、局域网服务
│       │   ├── db/     # 数据库层 (schema.sql + 迁移)
│       │   └── services/  # 扫描/关键帧/元数据/转换/重命名/备份等服务

└── docs/               # API 契约与数据模型文档
```

## 🚀 快速开始

### Windows 端

```bash
cd desktop
pnpm install
# 首次使用前下载 FFmpeg（元数据/封面/关键帧/转换需要，约 100MB）：
powershell -ExecutionPolicy Bypass -File scripts/download-ffmpeg.ps1
pnpm dev          # 开发模式
pnpm build        # 构建产物到 out/
```

> FFmpeg 二进制位于 `desktop/resources/ffmpeg/`（不入库）。也可设环境变量 `VM_FFMPEG_DIR` 指向已有 ffmpeg 目录，或加入系统 PATH。

### Android 端

```bash
cd android
flutter pub get
flutter run
```

### 局域网连接

1. 电脑与手机连接同一局域网。
2. Windows 端「设置 → 局域网服务」开启服务，记录端口与 6 位配对码。
3. 手机打开 App，填写电脑地址与端口、输入配对码完成配对。
4. 首次启动若弹出 Windows 防火墙提示，请选择「允许访问」。
